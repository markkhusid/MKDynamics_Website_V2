# Qt particle viewer

Created with Grok Build

`cpp_fortran` is a Qt Widgets window in front of a Fortran particle system. The Fortran types stay on the Fortran side. A bind(C) module publishes a C API, and the C++ window calls that API.

Qt Widgets is not installed on this machine, so the window was not built and this page has no capture of it. gfortran 14.2.0 did compile the Fortran sources. The figure uses the canvas color rule from `particle_canvas.cpp`. It is a drawing of that rule, not a frame from the Qt program.

## Fortran types

`ParticleSystem` holds positions, velocities, and radii. `init` takes the count and, optionally, `rmin`, `rmax`, and `v0`. The defaults are 0.005, 0.015, and 0.001. Positions are uniform on the unit square. Radii are uniform between `rmin` and `rmax`. Each velocity has magnitude `v0` and a random direction. `init_random_seed` seeds the generator from the clock.

`ParticleSimulation` holds a pointer to that system. One iteration checks collisions, checks the walls, then steps the positions. The default time step is `rmin / (10 v0)`.

A collision is an overlapping pair whose relative velocity points toward each other: the distance is below the sum of the radii, and the dot product of the separation with the velocity difference is negative. The update adds and subtracts `n * q` along the separation, with `q = dot(vdiff, n) / dot(n, n)`.

A wall test flips one velocity component when the center is less than one radius from a side, which includes a center that has left the square. The position is not moved back inside the square.

`write_sizes` and `write_positions` append to `particle.state`. The size writer uses the format `(2F12.5)` and passes one radius.

## Console driver

`main.f90` is a console driver in the same directory. The Qt `CMakeLists.txt` does not compile it. It allocates a system of 1000 particles, runs 1000 iterations, and deallocates both objects. Each iteration appends positions, so a full run writes a large `particle.state`. That file is not part of this page.

## C API

`particle_interface.f90` keeps one private system and one private simulation. The published names are `particle_system_init`, `particle_system_destroy`, `particle_system_run_iteration`, `particle_system_particle`, `particle_system_particle_count`, and `particle_system_params`. Indexes passed to `particle_system_particle` are Fortran indexes, starting at 1. `particle_interface.h` declares the same six functions in `extern "C"`. The comment under those declarations is an older interface and is not compiled.

## Window

`MainWindow` starts with 500 particles, radii 0.005 and 0.015, `v0` of 0.001, and a drawing size of 600. The form has a spin box up to 10,000, two line edits, a scaling slider from 100 to 2,000, Run, Pause, and Update. File → New and File → Open are in the form and have no slots in `mainwindow.cpp`.

Update reads the spin box and the two line edits, destroys the current system, and creates another. Run and Pause start and stop the canvas timer. The timer is started with no interval, so the default period is 0 ms. Each tick calls `particle_system_run_iteration` and repaints.

`paintEvent` fills the widget black, reads each particle from 1 through the count, and draws an ellipse of radius `r * maxSize` inside a square of side `maxSize` centered on the widget.
