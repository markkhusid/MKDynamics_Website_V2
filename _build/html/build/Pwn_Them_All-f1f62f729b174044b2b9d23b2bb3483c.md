# CSE543 Information Assurance and Security - Pwn Them All

Created with Grok Build

This was a sequence of small web services. Each one accepted something the browser sent and trusted it too far. The notes below name the failure and the fix. They leave out the requests, the secrets, and the flags.

## Client-side checks

One service decided a login in JavaScript running in the browser. Anyone can read that script and skip the branch. A password check has to run on the server, against a secret the page never receives.

## A field that becomes a command

Another page built a shell command out of a form field. A character that ends one command and starts another changes what the server runs. The fix is to keep form text as data. Pass it to a function that does not parse a command line.

## The request is not proof

Later services trusted a parameter, a hidden field, a cookie, or the User-Agent string to decide who the caller was. The browser, and any proxy in front of it, can set all of those. Identity has to come from a session the server created and can revoke.

## Source that should not be on the web

A script that stored account data was reachable as a file. Reading it showed how the service decided an administrator. Code that implements an access check does not belong at a downloadable URL.

## A query built from text

One service folded a parameter into a database query. The parameter then changed the query instead of staying a value. That is SQL injection. Queries should be parameterized. An automated injection tool is not part of this writeup.

## An encoded dump is still a dump

The last service returned a blob that decoded into account material. Encoding is not encryption. Anyone who received the response could read the blob.

## What stayed off this page

The original report includes host names, request traces, credentials, and flags. None of that is on this site.
